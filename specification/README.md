# UPD の基本規則

UPD の基本は、UI・Process・Data の仕事を分離し、その境界を保つことです。

## 1. 仕事を担当する層に置く

| 層 | 担当する仕事 | 置いてはいけない仕事 |
| --- | --- | --- |
| UI | 入力の受け取りと結果の表示。 | 業務やゲームのルールの判断、データの取得や保存。 |
| Process | アプリのルールに基づく判断、計算、処理の進行。 | 画面の操作、データベースやファイルの読み書き。 |
| Data | データの取得や保存、保存形式との変換。 | 画面の操作、業務やゲームのルールの判断。 |

表示のための整形は UI、保存形式への変換は Data に置きます。「判断」「変換」という言葉だけで所属を決めず、何のための仕事かで区別します。

## 2. UI と Data は直接やり取りしない

UI は Process に処理を依頼します。Process は必要なデータの取得や保存を Data に依頼します。

UI から Data を直接呼んではいけません。Data から UI を直接操作してもいけません。別の場所に処理を移しても、Process を通さずに UI と Data をつなげるなら、この規則に反します。

## 3. 結果も同じ境界を通して返す

Data の結果は Process に返し、Process の結果は UI に返します。成功した場合も、失敗した場合も同じです。

Process は結果を返し、UI がその見せ方を決めます。Data は読み書きの結果を返し、Process がアプリとしての扱いを判断します。

## 4. 層の間では必要な値を渡す

UI から Process へは、入力欄やボタンそのものではなく、入力された値を渡します。Data から Process へは、保存先の接続や操作を任せるための部品ではなく、取得したデータや保存結果を返します。

ほかの層の仕事を引き受けるために、その層の内部を直接操作してはいけません。
