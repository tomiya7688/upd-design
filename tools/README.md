# UPD 境界チェックツール

このディレクトリでは、**UPD の境界違反を検出し、修正するまで検査を通さないツール**を開発します。[必ず守る境界](../docs/developers/boundaries.md)が規則の本文です。

## 基本方針

- **違反はエラーです。** 検出した違反を警告だけで済ませず、非ゼロ終了として CI を失敗させます。
- **検査できない状態を合格にしません。** 未分類ソース、未対応言語、設定ミス、構文解析の失敗はエラーです。
- **名前より実際の処理を重視します。** 層のディレクトリは分類の手掛かりであり、責務を守る代わりにはなりません。
- **抜け道を検査します。** 相対importや共通部品経由など、解析器が対応する間接参照も検査します。
- **規則を緩めるための例外を追加しません。** 誤検出は検査器や正しい分類設定の改善で対処します。

## 最初の実装：Python の import 検査

`check_layers.py` は Python の構文木から import 先を調べ、コード上の禁止された層間依存を報告します。Python 標準ライブラリだけで動作します。

| 参照元 | 許可する参照先 | 禁止する参照先 |
| --- | --- | --- |
| UI | UI、Process、Shared | Data |
| Process | Process、Data、Shared | UI |
| Data | Data、Shared | UI、Process |
| Shared（任意） | Shared | UI、Process、Data |

**Shared は4つ目の処理層ではありません。** 値や型を共有するための補助領域です。そこへ処理を隠して層間の境界を迂回してはいけません。

この表は**コードの参照方向**の規則です。実行時の要求・結果の流れとは区別します。Data が Process に戻り値を返しても、Data が Process の具体的な実装を import する必要はありません。

### 設定

利用するプロジェクトのルートへ `upd-check.json` を置きます（フォルダ名は例であり、UPD の必須名ではありません）。

```json
{
  "source_roots": ["src"],
  "layers": {
    "ui": ["src/ui"],
    "process": ["src/process"],
    "data": ["src/data"],
    "shared": ["src/shared"]
  }
}
```

検査対象ソースが入るディレクトリを `source_roots` にすべて指定します。`shared` を使わなければ省略できます。指定した層のディレクトリは実在している必要があります。

### 実行

```sh
python /path/to/upd-design/tools/check_layers.py --root /path/to/your-project --config upd-check.json
```

CI でも同じコマンドを実行してください。`--config` は対象プロジェクトのルートからの相対パスまたは絶対パスです。

### 終了コードと診断

| 終了コード | 意味 |
| --- | --- |
| 0 | **対応する範囲の**静的解析で違反が見つからなかった |
| 1 | 違反、未分類ソース、未対応言語、解析失敗、検査できるソースなし |
| 2 | 設定不備などで検査を開始できなかった |

例えば以下のように、ファイル、行、規則番号と違反内容を表示します。

```text
src/ui/screen.py:2: UPD100 禁止された層間依存: ui → data (data.repository)
```

### 現在の検査範囲

**対応:** Python の `import`、`from ... import ...`、相対 import、文字列リテラルで指定する `__import__` と `importlib.import_module`。検査対象内の未分類 Python ソースと主な未対応言語のソースはエラーとします。

**未対応:** import なしで行う画面・保存操作、業務ルールの混入、変数で組み立てた動的参照、イベントや反射による実際の呼び出し、Python 以外の構文解析、設定した source_roots 外のソースの発見。

**現段階では、ツール成功＝UPDの全規則への適合ではありません。** 開発者は[レビューのチェックリスト](../docs/developers/review-checklist.md)も使ってください。

## テスト

```sh
python -m unittest discover -s tools/tests -v
```

GitHub Actions ではこのテストを実行します。これは**チェッカー自身のテスト**です。利用先プロジェクトの境界検査は、そのプロジェクトの CI に上記の CLI コマンドを登録してください。

今後は言語別の構文解析と、業務・表示・保存の責務が混入しているかを調べる検査を拡充していきます。その際、検出範囲と限界を必ず明記します。
