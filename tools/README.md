# UPD 境界チェックツール

[English](en/README.md)

本ディレクトリには、**検出可能な UPD の境界違反をエラーとする検査ツール**を置く。境界の必須規則は [開発者向けの規定](../docs/developers/境界.md) に定める。

## 対応言語と検査範囲

| 言語 | 拡張子 | 現在検査する構文 |
| --- | --- | --- |
| Python | `.py` | `import`、`from`、一部の定数文字列による動的 import（Python AST） |
| C# | `.cs` | 名前空間宣言、`using`（`global` や別名を含む） |
| Rust | `.rs` | `crate::`、`super::` による明示的な参照 |
| Go | `.go` | `go.mod` に基づくローカルパッケージの `import` |
| Kotlin | `.kt`、`.kts` | `package` 宣言と `import` |
| C++ | `.cpp`、`.cc`、`.cxx`、`.h`、`.hpp`、`.hh`、`.hxx` | ダブルクォート形式のローカル `#include` |
| なでしこ3 | `.nako3` | `!「ファイル」を取り込む`、`!『ファイル』を取り込む` |

**各言語の完全な構文解析には対応していない。** 現段階の検査対象は、代表的な静的参照構文に限られる。なでしこ1の `.nako` および `.nako2` は未対応としてエラーにする。

## 層間参照の規則

| 参照元 | 許可する参照先 | 禁止する参照先 |
| --- | --- | --- |
| UI | UI、Process、Shared | Data |
| Process | Process、Data、Shared | UI |
| Data | Data、Shared | UI、Process |
| Shared（任意） | Shared | UI、Process、Data |

Shared は第4の処理層ではない。共有部品を経由して責務境界を迂回することも禁止する。

表は **コードの参照方向**を定める。Data が Process に結果を返すことと、Data が Process の内部実装を参照することは別である。

## 設定

検査するプロジェクトに `upd-check.json` を置く。以下のディレクトリ名は設定例であり、UPD が要求する固定の名称ではない。

~~~json
{
  "source_roots": ["src"],
  "layers": {
    "ui": ["src/ui"],
    "process": ["src/process"],
    "data": ["src/data"],
    "shared": ["src/shared"]
  }
}
~~~

設定したディレクトリは実在しなければならない。Shared を使用しない場合は `shared` の指定を省略できる。

検査対象のソースは、指定した `source_roots` に含める。対象外に置いたファイルは検査されないため、検査範囲の設定にも注意を要する。

## 実行方法

実行には Python 3.11 以上を使用する。標準ライブラリ以外の Python パッケージは必要としない。

~~~sh
python /path/to/upd-design/tools/check_layers.py --root /path/to/project --config upd-check.json
~~~

`--root` は検査対象プロジェクトのパスである。`--config` には `--root` からの相対パスまたは絶対パスを指定する。

C# と Kotlin は検査対象内の名前空間・パッケージ宣言を照合する。Go は `go.mod` を用いる。Rust はソースのパスから参照先の位置を推定する。C++ と なでしこ3 はローカルファイルへの参照を照合する。

## 終了コード

| コード | 意味 |
| --- | --- |
| `0` | **対応する静的参照構文の範囲で**違反を検出しなかった |
| `1` | 境界違反、未分類ソース、認識可能な未対応拡張子、解析・解決不能、検査対象なし |
| `2` | 設定不備などにより検査を開始できなかった |

診断には、ファイル・行・規則番号・違反内容を含める。

~~~text
src/ui/View.cs:1: UPD100 禁止された層間依存: ui → data (Demo.Data)
~~~

検出した違反がある場合、利用プロジェクトの CI を失敗させる。継続的な適用には、利用プロジェクト側で本コマンドを CI の必須チェックとして設定する必要がある。

## 検査の限界

**終了コード `0` は、UPD の全規則への適合を証明しない。** 例えば UI 内で割引額を直接計算しても、禁止された層間参照がなければ検出できない。

言語別の主な未対応範囲は以下のとおりである。

- **C#**：`using` を伴わない完全修飾名、条件付きコンパイル、生成コードの意味解析。
- **Rust**：マクロ、グループ化した `use`、`path` 属性、複雑なモジュール構成。
- **Go**：`go.mod` のないローカル構成、ビルドタグ、生成コード、実行時の振る舞い。
- **Kotlin**：`import` を伴わない完全修飾参照、実行時の呼び出し。
- **C++**：山括弧形式の `#include`、マクロ、ビルドシステムの include path、関数間の呼び出し関係。
- **なでしこ3**：外部プラグイン、URL・貯蔵庫からの取り込み、動的参照、取り込み構文を介さない呼び出し。
- **共通**：言語間の実行経路、コメントや文字列の完全な字句解析、処理の意味に基づく責務違反。指定した `source_roots` 外のファイルや未知の拡張子も対象外となる。

**未対応の構文を検査済みとして扱ってはならない。** 各言語の正式な構文解析器やビルド情報との連携、責務の意味解析は今後の拡張対象である。

## テストと CI

~~~sh
python -m unittest discover -s tools/tests -v
~~~

本リポジトリの GitHub Actions は **チェックツール自体のテスト**を実行する。利用プロジェクトの境界を検査するには、そのプロジェクトの CI に別途コマンドを登録する。

なでしこ3の取り込み構文については、[公式リポジトリ](https://github.com/kujirahand/nadesiko3)および[開発者による解説](https://qiita.com/kujirahand/items/bdbf611fc1f448e63bf9)を参照する。
