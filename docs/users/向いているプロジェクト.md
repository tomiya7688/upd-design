# UPD が向いているプロジェクト

[English](en/suitable-projects.md)

**UPD は、外部とのインターフェースを持つプロジェクト向けの設計です。**

UI は人間用の画面に限りません。人・機器・ほかのシステムから要求を受け、結果を返す窓口も UI です。データの取得・保存は Data が担当します。

**外部との接点がなく、内部だけで自律的に動くプロジェクトには向きません。**

## 規模別の目安

| 規模 | 適性 | 例 |
| --- | --- | --- |
| 小規模 | 条件付き | 家計簿など、入力・計算・保存があるアプリなら有効。表示だけなら効果は小さい。 |
| 中規模 | 特に向いている | 予約・在庫管理など、入力・判定・データ管理を分けたいアプリ。 |
| 大規模 | 有効。ただし別の設計も必要 | ECサイトや業務システム。UPDは責務を分けるが、機能間の分割や運用までは定めない。 |

規模は目安です。**外部との接点があるか、分けるべき仕事があるか**を先に確認します。

## 特に向いている処理

- **外部から要求を受けて判断する**：予約受付、機器からの操作要求。
- **ルールや計算が多い**：料金計算、在庫判定、ゲームの勝敗。
- **取得元や保存先が複数ある**：データベース、CSV、外部API。
- **同じルールを複数の窓口から使う**：利用者画面と管理画面など。

## 向かない場合

- **外部とのやり取りがない、自律的に完結する処理**：UI の役割がない。
- **表示だけのページや単純な一回限りの処理**：役割を分ける効果が小さい。

通信機器のように相手が人間でなくても適用は可能です。ただし、**外部インターフェースがあるだけで、必ずUPDに向いているわけではありません。**
