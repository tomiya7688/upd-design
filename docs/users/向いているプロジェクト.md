# UPD が向いているプロジェクト

[English](en/suitable-projects.md)

**UPD は、外部とのインターフェースを持つプロジェクト向けの設計である。**

UI は人間用の画面に限らない。人・機器・ほかのシステムから要求を受け、結果を返す窓口も UI に該当する。データの取得・保存は Data が担当する。

**外部との接点がなく、内部だけで自律的に動くプロジェクトには適さない。**

## 規模別の目安

| 規模 | 適性 | 例 |
| --- | --- | --- |
| 小規模 | 条件付きで有効 | 家計簿など、入力・計算・保存の役割があるアプリケーション。表示だけの機能では効果が小さい。 |
| 中規模 | 特に適している | 予約・在庫管理など、入力・判定・データ管理を分離するアプリケーション。 |
| 大規模 | 有効だが別の設計も必要 | ECサイトや業務システム。UPD は責務を分けるが、機能間の分割や運用までは定めない。 |

規模はあくまで目安である。**外部との接点と、分離すべき仕事の有無**を優先して判断する。

## 適している処理の特徴

- **外部の要求に応じて判断する**：予約受付、機器からの操作要求。
- **ルールや計算が多い**：料金計算、在庫判定、ゲームの勝敗。
- **取得元や保存先が複数ある**：データベース、CSV、外部API。
- **複数の窓口で同じルールを使う**：利用者画面と管理画面など。

## 適さない場合

- **外部とのやり取りがなく、自律的に完結する処理**：UI の役割が存在しない。
- **表示だけのページや単純な一回限りの処理**：責務分離による効果が小さい。

通信機器のように、相手が人間でなくても UPD を適用できる。ただし、**外部インターフェースが存在するだけで、適性が決まるわけではない。**
