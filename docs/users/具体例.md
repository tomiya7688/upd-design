# 具体例で理解する UPD

[English](en/examples.md)

UPD では、操作をそのままひとつの仕事と考えず、**その中の入力・判断・読み書き・表示を分けます。**

## 例1：商品を検索する

利用者が検索欄に文字を入力し、検索ボタンを押します。

| 手順 | 担当 | 仕事 |
| --- | --- | --- |
| 1 | UI | 検索欄の文字を受け取る |
| 2 | Process | 検索条件を確認する |
| 3 | Data | 条件に合う商品を取得する |
| 4 | Process | 取得結果をアプリのルールに沿って整理する |
| 5 | UI | 商品を画面に表示する |

検索結果の順位をアプリのルールで決めるなら Process、カードや表のどちらで見せるかは UI の担当です。

## 例2：注文を保存する

購入ボタンが押されたら、UI は注文したい商品と数量を Process に伝えます。

Process は注文の条件を確認し、計算が必要なら行います。保存する内容を決めたら Data に保存を依頼します。Data は保存結果を返し、Process がアプリとしての結果を判断して UI に伝えます。

**保存処理を依頼しただけで「保存できた」と表示しないこと**も大切です。保存の完了を確認してから、UI が結果を表示します。

## 例3：ゲームの勝敗を表示する

UI は操作を受け取り、Process がゲームのルールに従って勝敗を判断します。UI は Process から受け取った結果を表示します。

記録を保存する必要があれば、Process が Data に依頼します。保存が不要なら、Data を通る必要はありません。

## 分離できていない例

- UI が直接データベースにアクセスして商品を取得する。
- UI が購入の許可や割引の最終判断を行う。
- Data が勝敗を判断する。
- Process が画面の色や配置を操作する。

どれも、ある層が別の層の仕事を引き受けています。

## 覚えておくこと

同じ「検索」「購入」という機能の中でも、仕事の種類は複数あります。**機能を分けるだけでなく、その機能の中の責務も分ける**ことが UPD の基本です。

さらに詳しい条件は [開発者向け：必ず守る境界](../developers/境界.md) を参照してください。
