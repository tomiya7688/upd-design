# 境界チェックツールの利用

UPD の境界は、実装・レビューで必ず守ります。違反が見つかった場合は、**修正するまで取り込みません。**

`tools/` では、境界違反を検出したら失敗するツールを整備します。[ツールの使い方と検査範囲](../../tools/README.md)を参照してください。

## CI に組み込む

検査対象プロジェクトの層の位置を設定し、開発中だけでなく、プルリクエストや CI でも検査します。違反・未対応言語・解析失敗・設定不備などで非ゼロ終了したら、CI を失敗させます。

検査を通すために対象ファイルを設定から外すのではなく、正しく分類して違反を修正してください。

## 自動検査の限界

**依存関係の検査と、処理が担当する仕事の検査は別です。** 例えば UI に割引計算を直接記述していても、ほかの層を import していなければ、import の検査だけでは分かりません。

したがって初期ツールが成功しても、すべての UPD 規則を満たす保証にはなりません。[必ず守る境界](boundaries.md)と[レビューのチェックリスト](review-checklist.md)も確認します。

解析器を増やす際は、検出できる違反と検出できない条件を明示します。検出できなかったことを「違反が存在しない」と言い換えません。
