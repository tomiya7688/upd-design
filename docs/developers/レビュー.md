# レビューのチェックリスト

[English](en/review-checklist.md)

本チェックリストは、UPD に基づく実装・変更のレビューで責務境界を確認するためのものである。

**チェック項目の省略によって必須規則が緩和されることはない。** 規則の本文は [必ず守る境界](境界.md) に定める。

## UI

- [ ] UI が外部からの要求を受け付け、結果の返却・表示を担当している。
- [ ] 業務・ゲームのルールに基づく最終判断や計算が UI に存在しない。
- [ ] UI がデータの取得・保存を直接実行していない。
- [ ] UI の画面部品を Process に操作させていない。

## Process

- [ ] アプリケーションのルールに基づく判断・計算が Process に置かれている。
- [ ] Process が画面部品や表示内容を直接操作していない。
- [ ] Process がデータベースやファイルを直接読み書きしていない。
- [ ] 必要なデータの取得・保存を Data に依頼している。

## Data

- [ ] Data が取得・保存、取得データの形式の正規化、保存形式への変換、入出力の失敗検出を担当している。
- [ ] Data の正規化によって元データの意味が変更されていない。
- [ ] 業務ルールによる欠損値の補完や判断が Process に置かれている。
- [ ] Data がアプリケーションのルールを判断していない。
- [ ] Data が画面を操作したり、UI に結果を直接通知したりしていない。

## 層間の受け渡し

- [ ] UI と Data の間に直接の要求・結果通知が存在しない。
- [ ] 共通関数やイベントによって責務境界が迂回されていない。
- [ ] 層間では必要な値と結果だけを渡し、他層の内部処理を代行させていない。
- [ ] 正常時と失敗時の双方で責務境界が保たれている。
- [ ] ファイル名や配置ではなく、実際の処理内容を基準に確認している。

## 分離の効果に関する確認

次の項目は必須規則の違反判定ではなく、設計上の確認観点である。

- [ ] 表示方法だけの変更で、アプリケーションの判断処理まで修正する必要がないか。
- [ ] ルールの変更を、保存先の実装と切り離して検証できるか。
- [ ] Data の変更が UI に及ぼす影響を説明できるか。
- [ ] 各層と層間の受け渡しをそれぞれテストできるか。

機能仕様によっては複数の層に変更が及ぶ。その場合も、**各層で変更する理由と責務が一致していること**を確認する。
