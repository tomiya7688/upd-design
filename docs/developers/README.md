# UPD 開発者ガイド

この文書は、UPD に沿ってコードを実装・レビューする開発者向けです。

**UPD の中心は、UI・Process・Data の責務を明確に分け、境界を破らないことです。** 名前やファイルの置き場所ではなく、処理が実際に何をしているかで判断します。

## 各層が担当する仕事

| 層 | 担当 | 担当しない仕事 |
| --- | --- | --- |
| UI | 入力の取得、表示の整形、描画、画面の状態 | アプリのルールの最終判断、データの取得・保存 |
| Process | 業務・ゲームのルール、計算、処理の判断 | 描画、画面部品の操作、保存先の読み書き |
| Data | データの取得・保存、保存形式との変換、入出力の失敗検出 | 画面操作、業務・ゲームのルールの判断 |

境界の規則は [必ず守る境界](boundaries.md) にまとめています。**これらは推奨事項ではなく、UPD として守る条件です。**

## 処理の流れ

    要求：UI → Process → Data
    結果：Data → Process → UI

これは責務上の流れを表します。関数呼び出し、非同期処理、通知など、連携の実現方法を固定する図ではありません。

画面だけで完結する操作は UI の中で行えます。データを必要としない計算は UI → Process → UI で完結できます。すべての処理で3つの層を必ず経由させるために、不要な仕事を増やす必要はありません。

## 実装の進め方

まず、機能を「入力と表示」「判断と計算」「取得と保存」に分解します。次に、層の間で渡す値と結果を決めます。最後に、各層が自分の仕事だけをしているか確認します。

特定のファイル構成、プログラミング言語、クラス数、依存性の注入方法は UPD の条件ではありません。**実装方法の自由と、責務の境界を越える自由は別です。**
