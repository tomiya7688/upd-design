# UPD 開発者ガイド

[English](en/README.md)

本書は、UPD に基づく実装とレビューの基本方針を示す。

**UPD の基本原則は、UI・Process・Data の責務を分離し、その境界を維持することである。** 判断基準はファイル名や配置ではなく、処理が実際に担う仕事にある。

## 各層の責務

| 層 | 担当する仕事 | 担当してはならない仕事 |
| --- | --- | --- |
| UI | 外部からの要求の受け付けと結果の返却・表示。画面がある場合はその表示処理 | アプリケーションのルールに基づく最終判断、データの取得・保存 |
| Process | 業務・ゲームのルール、計算、処理の判断 | 画面部品の操作、データベースやファイルの直接的な読み書き |
| Data | データの取得・保存、取得時の形式の正規化、保存形式への変換、入出力の失敗検出 | 画面操作、業務・ゲームのルールの判断 |

UI は人間用の画面に限定されない。機器やほかのシステムからの要求を受け付ける窓口も UI に該当する。

[必ず守る境界](境界.md) に定める禁止事項は、推奨ではなく **UPD の必須条件**である。

## 責務上の流れ

    要求：UI → Process → Data
    結果：Data → Process → UI

この図は責務上の受け渡しを表す。関数呼び出しやイベントなど、技術的な実現方法は規定しない。データの取得・保存が不要な操作まで3層を経由させる必要はない。

## 実装の基本手順

1. 機能を「外部との入出力」「判断・計算」「データの取得・保存」に分解する。
2. 各層に渡す値と、返す結果・失敗を定める。
3. 各処理が担当する層の責務を越えていないか確認する。

**実装方式の選択は自由である。ただし、責務境界の違反は許容しない。**

## 自動検査

[`tools/`](../../tools/README.md) に、検出可能な境界違反をエラーとする検査ツールを置く。

現時点では静的参照の一部だけを検査する。**自動検査への合格は全規則への適合を保証しない。** [検査の導入と限界](検査ツール.md) を参照し、コードレビューも併用する。
