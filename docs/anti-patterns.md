# 避けたい設計

UPD では、入力と表示、判断と計算、データの取得と保存を混ぜません。ここでは、仕事が混ざる例と直し方を示します。

## UI がデータベースを直接読む

**混ざっている例：** 検索ボタンの処理の中で、データベースから商品を読み出します。

**直し方：** UI は Process に検索を依頼します。Process は Data に商品の取得を依頼し、受け取った結果を UI に返します。

## UI が業務上の金額を計算する

**混ざっている例：** 画面の表示処理の中で、割引条件を確認し、支払金額を計算します。

**直し方：** 割引条件の判断と支払金額の計算は Process に置きます。UI は計算結果を受け取り、金額の表示を整えます。

## Process が画面の見た目を決める

**混ざっている例：** Process が、画面の文字を赤くしたり、画面部品を隠したりします。

**直し方：** Process はアプリ上の状態を返します。UI が、その状態をどう見せるかを決めます。

## Data が業務上の判断を行う

**混ざっている例：** データベースから商品を読む処理の中で、利用者が購入できるかどうかまで判断します。

**直し方：** 購入条件の判断は Process に置きます。Data は判断に必要なデータを取得して返します。

保存先の重複や接続失敗を検出するのは Data の担当です。その事実をアプリとしてどう扱うかは Process が判断します。

## フォルダだけを分ける

**混ざっている例：** UI・Process・Data のフォルダはあるものの、UI の処理が画面表示、業務上の計算、データ保存をすべて行っています。

**直し方：** 名前や置き場所だけでなく、仕事そのものを分けます。入力と表示は UI、判断と計算は Process、取得と保存は Data が担当します。

規則は[基本規則](../specification/README.md)を参照してください。
