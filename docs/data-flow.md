# 要求と結果の流れ

要求は UI → Process → Data、結果は Data → Process → UI の順に渡します。

## 商品を検索する

```text
UI：検索欄の文字を読み、検索を依頼する
  ↓
Process：検索条件を確認し、商品の取得を依頼する
  ↓
Data：条件に合う商品を取得する
  ↓
Process：取得したデータから、アプリのルールに従って結果をまとめる
  ↓
UI：商品一覧を表示する
```

UI が渡すのは検索文字です。Process は検索条件を確認し、データが必要なら Data に取得を依頼します。条件を満たさない場合は、Data を呼ばずにその結果を UI へ返します。

Data は取得した商品情報を Process に返します。Process は検索結果を UI に返し、UI が画面に表示します。商品の並べ方や表示する文字の整形は UI の担当です。ここでいう並べ方は画面上の配置を指し、検索順位などアプリのルールによる判断とは区別します。

## データを保存する

```text
UI：入力された内容を渡す
  ↓
Process：内容を確認し、保存するデータを決める
  ↓
Data：データを保存し、結果を返す
  ↓
Process：保存できたかどうかを UI に返す
  ↓
UI：保存結果を表示する
```

保存してよい内容かを判断するのは Process、保存先に書き込むのは Data、利用者へ結果を見せるのは UI です。

## 失敗したとき

失敗したときも、Data から UI へ直接通知しません。

たとえば、Data が保存先への接続失敗を検出したら、その事実を Process に返します。Process は保存を完了できなかったことを UI に返し、UI が案内を表示します。Data がダイアログを表示することはありません。

結果が逆向きに戻ることと、Data が UI を操作することは別です。

## 必要な仕事がある層を使う

画面の説明を開閉するだけなら、UI の中で完結します。入力された値だけで計算でき、データの取得も保存もしないなら、UI → Process → UI で完結します。

すべての操作を3層に通すのではなく、その操作に必要な仕事を各層が担当します。
