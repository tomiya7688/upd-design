# UPD Design

UPD は、アプリケーションの仕事を **UI・Process・Data の3つに分離する**設計の考え方です。

**入力と表示、判断と計算、データの取得と保存を混ぜず、それぞれの担当を明確にします。**

## 3つの役割

| 層 | 担当すること | 例 |
| --- | --- | --- |
| UI | 利用者の入力を受け取り、結果を表示する。 | 検索欄の文字を読み、商品一覧を表示する。 |
| Process | アプリのルールに従って判断し、計算や処理を進める。 | 検索条件を確認し、必要な商品の取得を依頼する。 |
| Data | データを取得し、保存する。 | データベースやファイルから商品を読み出す。 |

「層」は、担当する仕事ごとに分けたまとまりです。

## やり取りの流れ

```text
要求：UI → Process → Data
結果：Data → Process → UI
```

UI は Process に処理を依頼し、Process は必要なデータの取得や保存を Data に依頼します。結果は逆の順序で返します。UI と Data は直接やり取りしません。

画面の説明を開閉するだけなら UI の中で完結します。取得や保存が不要な計算なら、UI と Process で完結します。

## 分離する目的

画面の見せ方を変えるときは UI、アプリのルールを変えるときは Process、データの読み書きの方法を変えるときは Data を中心に見直せるようにします。

フォルダを3つに分けるだけではなく、**仕事の担当を分けること**が UPD の中心です。
