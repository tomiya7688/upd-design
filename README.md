# UPD Design

[English](en/README.md)

**UPD は、アプリケーションの仕事を UI・Process・Data の3つに分離する設計の考え方である。**

UPD の対象は、外部とのインターフェースを持つプロジェクトである。UI の相手は人間に限らず、機器やほかのシステムも含む。外部との接点がなく、自律的に完結するプロジェクトには適さない。

UPD の中心は、フォルダやクラスの名前ではなく、**仕事の責務を混在させないこと**にある。

| 層 | 責務 |
| --- | --- |
| **UI** | 外部からの要求の受け付け、結果の返却・表示 |
| **Process** | アプリケーションのルールに基づく判断・計算・処理 |
| **Data** | データの取得・保存 |

## 守るべき境界

**各層は担当外の仕事を行ってはならない。** 特に、UI と Data の直接的なやり取りは禁止する。

    要求：UI → Process → Data
    結果：Data → Process → UI

この図は責務上の受け渡しを示す。特定のクラス構成や通信方式を要求するものではない。また、すべての操作に3層が必要なわけではない。

## ツール

[`tools/`](tools/README.md) では、UPD の境界違反を検出して検査を失敗させるツールを開発する。

現在の検査対象は、Python、C#、Rust、Go、Kotlin、C++、なでしこ3の代表的な静的参照構文である。**責務違反のすべてを検出するものではない。** 詳細は [ツールの説明](tools/README.md) に示す。

## 文書の言語と文体

`README.md` は日本語を標準とし、英語版を [`en/README.md`](en/README.md) に置く。各文書の日本語版には日本語のファイル名、英語版には英語のファイル名を使用する。

日本語の設計文書は**常体（だ・である調）**で記述する。責務の定義には断定形、禁止事項には「〜してはならない」を用い、文末の丁寧語は使用しない。
