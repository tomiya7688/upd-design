# UPD Design

UPD は、アプリケーションの仕事を **UI・Process・Data** の3つに分けて考える設計です。

大切なのは、**「何をする仕事なのか」によって担当を分けること**です。

## 3つの役割

| 分類 | 担当する仕事 |
| --- | --- |
| **UI** | 利用者からの入力を受け取り、結果を表示する。 |
| **Process** | アプリのルールに沿って判断し、計算や処理を行う。 |
| **Data** | データを取得し、保存する。 |

たとえば、商品を検索する機能なら、検索欄の入力や結果の表示は **UI**、検索条件の確認は **Process**、商品データの取得は **Data** の仕事です。

## なぜ分けるのか

画面の見せ方、アプリのルール、データの保存方法は、それぞれ変更する理由が異なります。

仕事を分けておくと、変更する場所を見つけやすくなり、ほかの仕事への影響も把握しやすくなります。また、それぞれの仕事を個別に確認しやすくなります。

## UPD で大切にすること

**名前やフォルダを3つに分けるだけでは、UPD の分離にはなりません。**

UI にアプリのルールを詰め込んだり、Data に画面の表示処理を持たせたりせず、処理の目的に合わせて担当を分けます。

UPD が示すのは、この **仕事の分離という考え方** です。具体的な部品の構成や、部品同士をどうつなぐかは、プロジェクトごとに決めます。
